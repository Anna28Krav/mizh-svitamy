Меню та рецепти

Адміністратор змінює ціни, склад і добірки. Гість бачить збережене меню та може створити власний напій.

↗

Замовлення без плутанини

Сервер перевіряє замовлення й зберігає його в базі. Залишки оновлюються разом із замовленням, а повторний запит не створює його копію.

☾

Злагоджена робота бариста

Робочі станції отримують замовлення зі спільної черги. Одне замовлення не потрапляє в роботу на двох станціях одночасно.

⌁

Спільні дані кав’ярні

Меню, замовлення й залишки зберігаються в хмарній базі. Завантажені фото — у файловому сховищі. Команда працює з тими самими даними через інтернет.

✦

Паралельні обчислення

Фонові потоки браузера ділять записи про замовлення на частини, підраховують їх одночасно та об’єднують підсумки. Час обох способів можна порівняти у вкладці «Обчислення».

Технології проєкту
HTTP API
Зв’язок сторінок із серверними модулями меню, замовлень і робочої черги.
Supabase PostgreSQL
Хмарна база даних для замовлень, меню, залишків і налаштувань.
Supabase Storage
Файлове сховище завантажених фотографій, контенту й даних квитанцій.
Web Workers
До чотирьох фонових потоків браузера для паралельного підрахунку.
Supabase Edge Functions
Серверні модулі працюють в одному застосунку. Станції бариста — його мережеві клієнти; вони не є окремими серверами обчислень.
TypeScript
Типізований код серверних модулів: допомагає узгоджувати структуру меню, рецептів і замовлень.
SVG
Векторні ілюстрації чашок, інгредієнтів і зірок. Разом із JavaScript вони відтворюють анімацію приготування напою.
Supabase Auth та ролі
Вхід до акаунта гостя або команди. Сервер перевіряє робочу роль і код доступу перед відкриттям захищених дій.

Онлайн-оплата поки імітується без списання коштів. Квитанція підтверджує дані замовлення та не є фіскальним чеком.
